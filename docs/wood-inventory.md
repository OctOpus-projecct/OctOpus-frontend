# 목재 지급과 인벤토리 시제품

벌목 성공 시 서버가 작업자에게 목재를 한 번 지급한다. 같은 목재는 한 항목에 수량을 누적한다. 서버가 확정한 소유자의 상태만 인벤토리에 표시한다. 다른 플레이어의 수량/무게는 인벤토리 동기화 대상이 아니다.

## 개발용 수치와 판정
목재 보상 12개, 개당 무게 1, 최대 소지 무게 100, 과적 이동속도 50%는 개발용 조정값이다. 최종 밸런스를 확정하지 않는다. 원본은 공용 InventoryRules다. 내부 무게는 표시 무게 1을 정수 1000 단위로 계산한다.

- 무게 95 이상: 새 벌목 시작 금지. 요청 시와 나무에 도착한 실제 시작 시점에 서버가 검사한다.
- 이미 진행 중인 벌목 성공: 전부 지급. 94에서 보상 12를 받으면 106이 된다.
- 무게 100: 새 벌목 금지, 이동속도 정상. 100 초과: 새 벌목 금지, 이동속도 감소.
- 실패·취소·만료·작업자 외 타격·성공 후 추가 타격에는 보상을 지급하지 않는다.
- 같은 작업을 다시 클릭해도 기한/보상을 초기화하지 않는다.

## 직접 확인
서버와 클라이언트를 함께 갱신해 실행한다. 기존 실행 파일은 실행 중 자동 갱신되지 않는다.
1. Connect 후 내 인벤토리가 Wood 0, Weight 0 / 100으로 표시되는지 확인한다.
2. 나무를 몇 번만 타격하면 목재가 늘지 않아야 한다. 지면 클릭으로 취소해도 동일하다.
3. 나무 체력이 0이 되면 작업자의 Wood가 12 증가한다. 다른 창의 내 Wood는 그대로다.
4. 성공 후 Space를 더 눌러도 수량이 추가로 늘지 않아야 한다. 다른 나무 성공 시 같은 Wood 항목에 누적된다.
5. 기본 보상으로 8번 성공하면 96이 되어 새 벌목이 차단되지만 이동은 정상이다. 과적은 자동 검증의 94→106 시나리오로 확인한다.
6. UI 클릭이 이동/벌목 취소를 일으키지 않고 무게/제한 안내를 스크롤해서 볼 수 있는지 확인한다.

## 저장 범위
현재는 접속 중 상태만 관리한다. Disconnect/재접속 또는 서버 재시작 시 소지품이 초기화된다. 계정별 저장 요구사항은 유지하며 저장 구현은 다음 단계다. 현재 장기 운영용 인벤토리로 사용하지 않는다. 버리기·줍기·판매·창고·교환 및 생활 경험치는 이번 범위에 없다.

## 검증 명령
서버/클라이언트 빌드 후 프런트엔드에서 실행한다. 기존 서버를 종료하고 같은 UDP 포트 테스트는 순차 실행한다.

```powershell
pwsh -NoProfile -File scripts/test-inventory-session.ps1 -Scenario normal
pwsh -NoProfile -File scripts/test-inventory-session.ps1 -Scenario overweight
```

외부 WSL 서버 사용 시 `-ExternalServer -ServerAddress WSL_IPV4`를 추가한다. overweight 시나리오는 서버 자체를 `-octopus-inventory-test-overweight`로 시작해야 하며 첫 접속자만 목재 94개로 준비한다. 일반 서버는 0개로 시작한다. 클라이언트에 테스트 인자를 넣어도 보상/수량을 조작할 수 없다. 테스트 서버는 다른 플레이어가 없는 환경에서 실행한다.

순수 규칙 테스트는 94/95/100/104 경계, 전량 지급, 감소 후 재평가와 잘못된 수량을 검증한다. 복수 클라이언트는 실제 서버 지급·무보상·개인 상태 격리·중복 요청·감속을 검증한다. 사용자 화면/조작 확인은 별도로 기록한다.

## 검증 기록 (2026-09-11)
- 공용 0.6.0, 태그 shared-v0.6.0-wood-inventory, SHA b72ed5fe7b6a6743847265cf868705aac746be1a를 양쪽 manifest/lock에 고정했다.
- 서버 PlayMode 45개, 클라이언트 PlayMode 21개가 통과했다. Windows 서버/클라이언트 및 Linux 전용 서버 빌드를 완료했다.
- Windows 두 클라이언트의 정상 0→12 및 과적 94→106 지급, 부분 작업·취소 무보상, 추가 타격 중복 지급 방지, 다른 플레이어 수량 비공개와 서버 이동 감속 검증이 통과했다.
- 구현과 분리된 코드/문서 리뷰에서 필수 지적 없음. 테스트의 이동 포함 대기 시간을 실제 맵 거리에 맞춰 보완했다.
- WSL 인벤토리 세션은 기존 사용자가 실행한 서버의 UDP 7770 점유로 시작하지 못했다. 기존 서버 종료 승인 또는 사용자가 종료한 후 재검증이 필요하다. Linux 빌드 통과를 WSL 접속 통과로 해석하지 않는다.
- 실제 인벤토리 화면/조작의 사용자 확인, 영속 저장, 10명 부하·원격 지연·공식 지원 Ubuntu·AWS는 남아 있다.
- 고정 Git 버전으로도 위 PlayMode/Windows 인벤토리 정상·과적 시나리오를 통과했고, 다중 나무 독립 작업·재생성 회귀 검증을 통과했다.
- 기존 벌목의 쿨다운·스태미나 부족/회복·취소·고갈·재생성·시간 초과 Windows 회귀 검증도 통과했다.

## 빠른 벌목 테스트 설정
사용자 요청으로 회복을 평상시 초당 100, 벌목 중 초당 50으로 높였다. 비용 25·타격 간격 0.6초는 유지하므로 연속 벌목이 가능하다. 나중에 공용 HarvestPrototypeSettings의 두 회복 값만 낮출 수 있다. 기존 스태미나 부족 회귀 검증은 전용 서버 인자 `-octopus-stamina-baseline-test`에서만 10/3을 사용하며, test-strike-session.ps1이 로컬 서버에 자동 적용한다. 외부 서버로 해당 회귀 검증을 실행할 때도 이 서버 인자가 필요하다.

빠른 회복 소비 버전은 0.6.1 / `980f532dd61ad2b59ecdc0c7e1462c5f1a32fc8b` / `shared-v0.6.1-fast-recovery`다. 앞의 0.6.0 검증 기록은 이전 수치 기준 이력이다.
빠른 회복 버전에서 Windows 서버/클라이언트·Linux 서버 빌드를 완료했다. Windows 실제 두 클라이언트 정상 인벤토리 검증을 통과했으며, 연속 유효 타격마다 서버 스태미나가 75로 유지되어 다음 타격까지 비용 25가 회복되는 것을 확인했다. 기존 WSL 서버는 실행 중이므로 새 버전 WSL 접속은 미검증이다.
전용 기본 회복 설정을 사용하는 기존 타격·소모·회복·재생성·시간 초과 Windows 회귀 검증도 통과했다.
