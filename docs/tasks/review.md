# 리뷰와 검증 기준

## 역할과 범위
- 모든 변경은 작성자가 diff와 완료 조건을 대조해 자체 검토한다.
- 게임 로직·통신·저장·검증 스크립트 변경은 구현과 분리된 검토를 진행한다. 별도 리뷰가 가능한 도구나 세션에 이슈·요구사항·대상 diff·검증 결과를 제공한다.
- 문서·템플릿만 바뀌는 작은 작업은 자체 검토와 문서 검증으로 충분하다. 규칙 충돌이나 큰 구조 변경은 별도 검토한다.
- 별도 검토는 작성자의 “정상 동작” 주장에 의존하지 않고 실제 코드와 근거를 확인한다.
- 별도 검토를 실행할 수 없으면 “별도 리뷰 미실행”이라고 보고한다. 자체 검토를 독립 리뷰로 표시하지 않는다.
- 사용자는 조작감·재미·시각적 표현과 최종 병합을 판단한다. AI 리뷰나 테스트가 플레이 확인을 대신하지 않는다.

## 확인할 사항
- 이슈 완료 조건과 기준 요구사항을 충족하는가? 미정 사항을 임의로 확정했는가?
- 서버가 권한·거리·장비·수량·상태를 검증하는가?
- 동시 요청·중복 요청·접속 종료·시간 경계에서 자원 복제·유실이 발생하는가?
- 두 저장소의 공용 타입·규칙·버전이 호환되는가?
- 오류·재접속·취소 후 UI와 서버 상태가 일치하는가?
- 해당 변경에 필요한 검증이 실제 실행되었는가? 관련 없는 리팩터링과 비밀값·생성 캐시가 포함되었는가?

## 변경별 필수 검증
| 변경 | 검증 |
|---|---|
| 문서·템플릿 | 문서 검사, 규칙 일관성, 템플릿 항목 확인 |
| 순수 게임 규칙 | 정상·실패·경계 조건의 관련 자동 테스트 |
| 나무 독점·아이템·재화·교환·저장 | 동시성·중복·취소·접속 종료 및 해당 저장 복구 검증 |
| UI·입력·장면 | 실제 엔진 동작·시각 확인, 관련 키 재설정 |
| 통신·공용 계약 | 양쪽 빌드와 복수 클라이언트 시나리오 |
| 빌드·배포 | 해당 환경의 빌드·기동·복구 절차 확인 |

게임 검증 도구는 아직 미설정이다. 현재 문서 CI 통과를 Unity 빌드·게임 테스트 통과로 표현하지 않는다.

## 지적과 수정
- 지적은 중요도, 파일·최소 행 범위, 발생 조건, 사용자 영향, 근거를 포함한다.
- P0: 즉시 대응할 심각한 장애·데이터 손상. P1: 주요 기능 실패·복제·유실·권한 문제. 병합 전 해결한다.
- P2: 특정 조건의 기능 결함. 원칙적으로 해결하며 미룰 경우 후속 이슈와 사용자 동의를 기록한다.
- P3: 사소한 개선. 선택적 제안으로 표시하며 개인 취향만으로 병합을 막지 않는다.
- 추측은 확인 필요 사항으로 표시한다. 문제를 찾지 못하면 “지적 없음”과 검토 범위·한계를 적는다.
- 수정자는 재현과 코드 근거를 확인한 뒤 고친다. 반박 근거가 있으면 설명하고 기계적으로 수용하지 않는다.
- 수정 후 해당 검증을 다시 실행한다. 동일 문제의 검토·수정이 반복되고 진전이 없으면 원인·시도·남은 결정을 사용자에게 보고한다.

## 하네스 개선
반복 결함은 재현 테스트·자동 검사·문서 보완 중 적절한 수단으로 예방한다. 규칙을 추가하면 읽을 경로와 실행할 검사를 함께 정한다. 사용되지 않거나 중복되는 규칙은 정리한다. 두 저장소의 공통 리뷰 규칙은 함께 갱신한다.
