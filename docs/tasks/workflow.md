# 개발·검증 절차

## 현재 상태
Unity 프로젝트, 패키지 버전, 게임 빌드·테스트 명령은 아직 없다. 문서 검사 스크립트와 GitHub Actions 설정은 추가되어 있으며, 원격 CI 실행은 아직 확인하지 않았다.

## 문서 검증
저장소 루트에서 PowerShell 7의 `pwsh -NoProfile -File scripts/check-docs.ps1`을 실행한다. 검사기 회귀 검증은 `pwsh -NoProfile -File scripts/test-check-docs.ps1`이다.

필수 지침·템플릿과 Markdown 인라인 파일 링크를 확인한다. 외부 URL·헤딩 앵커·참조형 링크는 검사하지 않는다. 상대 저장소가 없는 단독 체크아웃에서는 해당 링크를 명시적으로 SKIP하며, 양쪽이 있으면 함께 검사한다. GitHub에서는 `.github/workflows/docs.yml`의 `docs-check`가 PR·main 푸시에 같은 검사를 수행하도록 구성했다. 저장소 보호 규칙은 아직 설정하지 않았다.

이슈·커밋·리뷰는 [이슈 규칙](issues.md), [Git 절차](git-workflow.md), [리뷰 기준](review.md)을 따른다. 공통 규칙·템플릿·검사기를 수정하면 두 저장소를 함께 갱신한다.

## 작업 흐름
1. 기존 변경·관련 코드와 기준 요구사항을 확인한다.
2. 변경할 동작과 완료 조건을 정한다. 미정인 게임 규칙이 구현을 막으면 해당 사항만 질문한다.
3. 버그는 재현·원인을 확인하고 관련 부분만 수정한다.
4. 순수 로직은 관련 자동 검증, 장면·UI·입력은 엔진 검증, 동기화는 로컬 서버와 복수 클라이언트로 확인한다.
5. 문서 변경은 링크·규칙 일관성·변경 차이로 검증한다. 게임 실행을 검증한 것으로 보고하지 않는다.

## 저장소 경계
- 통신·공용 타입 변경은 백엔드 소유 패키지에서 먼저 다룬다. 클라이언트에 대체 정의를 만들지 않는다.
- 양쪽 배포 버전이 다를 수 있으므로 호환되는 패키지·계약 버전과 적용 순서를 명시한다.
- 백엔드 체크아웃이 없으면 실제 위치를 확인하거나 필요한 후속 작업을 알린다.

## 자산·Git
- Unity가 관리하는 자산 식별자와 `.meta`를 보존한다. 장면·프리팹 변경 후 참조를 확인한다.
- 초기 설정 때 Unity 캐시·로컬 설정·빌드 결과 제외 규칙을 추가하고 대용량 자산의 Git LFS 필요 여부를 판단한다.
- 사용자 변경은 보존하고, 새 브랜치의 기본 접두사는 `codex/`를 사용한다.
- 외부 모델·텍스처 등은 출처와 사용 조건을 확인한다. 자산 다운로드나 패키지 도입은 필요한 범위로 제한한다.

## 완료 보고
변경 이유, 검증한 명령·시나리오와 결과, 실행하지 못한 엔진 검증, 서버 동반 변경 여부를 보고한다. 커밋·푸시·배포를 실행하지 않았다면 완료한 것으로 표현하지 않는다.
